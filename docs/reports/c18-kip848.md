# Report: Consumer Group Protocol — KIP-848 (Item 18)

## Summary

Implemented the KIP-848 consumer group protocol (`ConsumerGroupHeartbeat` 68, `ConsumerGroupDescribe` 69), `DescribeTopicPartitions` (75), and the flexible versions of `Produce` (v9), `ListOffsets` (v6–7), `OffsetCommit` (v8–9), `OffsetFetch` (v6–9), and `FindCoordinator` (v3–4) against the Apache Kafka 4.4.0 message schemas. Added server-side `uniform` and `range` assignors, two-phase partition revocation, format level 5 (`snapshotVersion = 10`), simulator invariants and mutation testing (`UnsafeAssignBeforeRevoke`), and an integration test using Java `kafka-clients` 4.4.0 (`group.protocol=consumer`) and `kafka-consumer-groups.sh --describe`.

## What Was Built

1. **Wire protocol (`internal/wire`)**:
   - `internal/wire/consumer.go`: `ConsumerGroupHeartbeat` (68, v0–1), `ConsumerGroupDescribe` (69, v0–1), `DescribeTopicPartitions` (75, v0).
   - `internal/wire/groups.go`, `internal/wire/messages.go`, `internal/wire/api.go`: flexible encoding for `Produce` v9, `ListOffsets` v6–7, `OffsetCommit` v8–9, `OffsetFetch` v6–9 (batched `Groups` and v9 `MemberID`/`MemberEpoch`), `FindCoordinator` v3–4 (batched `Coordinators`), and KIP-848 error codes (`14`, `69`, `110`–`113`).
   - Verified with `TestMessagesRoundTripAtEveryVersion` including truncation checks at every byte offset.

2. **Broker state machine and handlers (`internal/broker`)**:
   - `internal/broker/consumer.go`: `cgroup`, `cmember`, `uniformAssign`, `rangeAssign`, `reconcile`, `cgNeedsApply`, `consumerHeartbeat`, `consumerGroupDescribe`, `describeTopicPartitions`, session and revocation timers (`cgTouch`, `cgSync`), and `ConsumerGroupCheck`.
   - `internal/broker/state.go`, `internal/broker/snapshot.go`: `cmdCGBeat` (19), `cmdCGRemove` (20), `formatLevel = 5`, `snapshotVersion = 10`, and `OffsetCommit` v9 member-epoch fencing (`ErrStaleMemberEpoch`).
   - `internal/broker/admin.go`, `internal/broker/groups.go`, `internal/broker/leader.go`, `internal/broker/node.go`: `ListGroups` reports `Type: "consumer"`, `DescribeGroups` returns `ErrGroupIDNotFound` on consumer-protocol groups, `JoinGroup` refuses mixing classic members into an active consumer-protocol group (`ErrInconsistentGroupProtocol`), and `refusal` covers the new APIs.

3. **Simulator & Mutation Testing (`internal/sim`)**:
   - `internal/sim/cg.go`: KIP-848 consumer group clients exercising `ConsumerGroupHeartbeat` v0–1, delayed revocation, `OffsetCommit` v8–9 (including stale-epoch zombie commits), `OffsetFetch` v8–9, `ConsumerGroupDescribe`, and `DescribeTopicPartitions`.
   - `internal/sim/monitor.go`: runs `ConsumerGroupCheck()` after every node event (invariant C1: no partition held by two members; C2: no partition targeted by two members).
   - `internal/sim/sim_test.go`: `assign a consumer partition before its owner revokes it` (`UnsafeAssignBeforeRevoke`) caught by **139 of 200 seeds** (first at seed 1).

4. **Integration Tests (`integration/`)**:
   - `TestJavaKIP848ConsumerGroup`: runs two Java 4.4.0 `KafkaConsumer` processes with `group.protocol=consumer` and `group.remote.assignor=uniform`, verifies `kafka-consumer-groups.sh --describe` (negotiating `ConsumerGroupDescribe` v1, `DescribeTopicPartitions` v0, `OffsetFetch` v9), kills one consumer with `SIGKILL` to exercise server-side session expiry and partition takeover, and restarts the broker mid-stream without duplicate deliveries.

## Bugs Found & Recorded

- `docs/BUGS.md` **C4**: `kafka-consumer-groups.sh --describe` threw `NullPointerException` in Kafka 4.4.0 when `DescribeTopicPartitionsResponse.EligibleLeaderReplicas` was encoded as null (`-1`); fixed to encode empty arrays (`0`).
- `docs/BUGS.md` **M21**: un-snapshotted `topicsVersion` / `cgroup.seen` caused `S4` state divergence on seeds 13, 105, and 1946 after snapshot restore; fixed by comparing `cg.meta` directly against `metaOf(s.subscribedTopics(cg))`.
- Classic/consumer protocol mixing: `JoinGroup` v5 with empty `MemberID` returned `ErrMemberIDRequired` before checking if the group already had active KIP-848 members; fixed in `joinGroup`.
