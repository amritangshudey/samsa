# Design C18: Consumer Group Protocol (KIP-848)

## 1. Goal

Implement the broker-side consumer group protocol of KIP-848 so that modern Kafka clients (including Java `kafka-clients` 4.4.0 with `group.protocol=consumer`) and `kafka-consumer-groups.sh` manage group membership, partition assignment, and offset commits through `ConsumerGroupHeartbeat` (API 68) and `ConsumerGroupDescribe` (API 69) without a client-side group leader or stop-the-world `JoinGroup`/`SyncGroup` barrier.

## 2. Wire Protocol

Added and updated in `internal/wire` against the Apache Kafka 4.4.0 JSON message schemas:

- **New APIs** (`internal/wire/consumer.go`):
  - `ConsumerGroupHeartbeat` (key 68, v0–1, flexible v0+)
  - `ConsumerGroupDescribe` (key 69, v0–1, flexible v0+)
  - `DescribeTopicPartitions` (key 75, v0, flexible v0+, used by `kafka-consumer-groups.sh --describe`)
- **Upgraded APIs** (`internal/wire/groups.go`, `internal/wire/messages.go`):
  - `Produce` v9 (flexible v9+)
  - `ListOffsets` v6–7 (flexible v6+)
  - `OffsetCommit` v8–9 (flexible v8+; `GenerationIdOrMemberEpoch` carries member epoch for KIP-848 groups)
  - `OffsetFetch` v6–9 (flexible v6+; batched `Groups` array from v8, `MemberId`/`MemberEpoch` validation from v9)
  - `FindCoordinator` v3–4 (flexible v3+; batched `CoordinatorKeys`/`Coordinators` from v4)
- **Error codes** (`internal/wire/api.go`): `ErrCoordinatorLoadInProgress` (14), `ErrGroupIDNotFound` (69), `ErrFencedMemberEpoch` (110), `ErrUnreleasedInstanceID` (111), `ErrUnsupportedAssignor` (112), `ErrStaleMemberEpoch` (113).

## 3. State Machine & Format Level 5

- **Format level 5** (`const formatLevel = 5`, `snapshotVersion = 10` in `internal/broker/state.go`, `internal/broker/snapshot.go`):
  - New Raft commands `cmdCGBeat` (19) and `cmdCGRemove` (20).
  - `ConsumerGroupHeartbeat` returns retriable `ErrCoordinatorNotAvailable` until the cluster reaches format level 5.
  - `cgNeedsApply` avoids proposing a Raft command when a steady-state heartbeat changes nothing (`epoch == m.epoch`, no subscription/assignor/rack/timeout/owned/topic-metadata changes, and `reconcile` produces no change).
- **Two-phase revocation invariant** (`internal/broker/consumer.go`):
  - Every partition (`tpKey{TopicID, Part}`) is in at most one member's `owned` set (`ConsumerGroupCheck` verifies this on applied state after every event).
  - When `retarget` moves a partition from member A to member B, `reconcile` does not add that partition to B's `owned` set while `heldByOther` is true, nor does it grant A new partitions while `A.revoking()` is true (`len(owned \ target) > 0`).
  - Only once A reports `Owned` without the revoked partition (or A leaves / expires on session or rebalance timeout) may B claim it.
- **Server-side assignors**:
  - `uniform` (default): sticky balanced assignment across subscribed members, minimizing partition movement while keeping counts within 1 where subscriptions permit.
  - `range`: per-topic contiguous partition ranges across subscribed members sorted by member ID.
- **Fencing**:
  - `OffsetCommit` checks `cg.checkCommit`: `ErrUnknownMemberID` if absent, `ErrStaleMemberEpoch` (113) if `epoch != m.epoch` (unless `UnsafeNoFencing`).
  - `OffsetFetch` v9 validates `MemberID` / `MemberEpoch` when supplied (`MemberEpoch >= 0`).
  - `ConsumerGroupHeartbeat` allows `prevEpoch` retry (re-sending the full current assignment if the previous response was lost) and fences any other mismatched epoch with `ErrFencedMemberEpoch` (110).

## 4. Deliberate Bug & Simulator Verification

- `Config.UnsafeAssignBeforeRevoke` skips the `revoking()` and `heldByOther()` guards in `reconcile`, assigning target partitions immediately before the previous owner revokes them.
- `internal/sim/cg.go` adds KIP-848 consumer group clients (`cgMember`), `monitor.go` calls `ConsumerGroupCheck()` after every node event, and `TestMutationSuite` verifies `UnsafeAssignBeforeRevoke` is caught by the simulator.
