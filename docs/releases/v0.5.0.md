# Samsa v0.5.0: single-server membership changes and rolling upgrades

Production plan milestone v0.5 (`docs/PRODUCTION.md`, items 9 and 10).

## What is new

- **Cluster membership changes** (C1, ADR 0022, ADR 0023): single-server Raft
  configuration changes (`AddRaftVoter` API 80, `RemoveRaftVoter` API 81),
  catching up new nodes as learners before promoting them to voters, Ongaro's
  2015 current-term commit guard between changes, peer listener addresses
  stored in the replicated configuration, `-join` flag, and `samsa node add` /
  `samsa node remove` CLI commands. Found and fixed `docs/BUGS.md` S9 (a node
  left alone by a configuration change must wait an election timeout on restart
  rather than campaigning immediately). Reports:
  `docs/reports/c1-membership-part-a.md`, `docs/reports/c1-membership-part-b.md`.
- **Rolling upgrade and cluster format level** (G7, ADR 0024): nodes report
  their supported format level to the leader, which raises the cluster's format
  level via `cmdSetLevel` only after every voter supports it; snapshots are
  encoded in the oldest version that holds their state; `TestRollingUpgrade`
  upgrades a three-node cluster under a live producer in CI. Report:
  `docs/reports/g7-rolling-upgrade.md`.

## Evidence

| | |
|---|---|
| Simulator | 3,000 seeds per CI run with voter additions and removals under faults; 0 failures |
| Mutations | concurrent configuration change, skipping learner catch-up, Ongaro erratum schedule, and `UnsafeRaiseLevelEarly` all caught |
| Real processes | 3 → 4 → 3 node cluster resize under a live producer; rolling upgrade under a live producer in CI |

## Upgrading from earlier releases

Rolling restart one node at a time with SIGTERM (`TestRollingUpgrade`). New
format-gated features return `UNSUPPORTED_VERSION` until the last voter has
upgraded and reported its level. Downgrading below a raised format level is not
supported.
