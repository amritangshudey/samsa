# Samsa v0.7.0: modern clients (topic IDs, KIP-848 consumer groups, follower fetch, fault kinds, profiles)

Production plan milestone v0.7 (`docs/PRODUCTION.md`, items 18a, 18, 19, 23a, and 24).

## What is new

- **Topic IDs and Kafka 3.1 protocol versions** (item 18a, ADR 0032, format level 4,
  snapshot v9): 16-byte deterministic UUID per topic; `ApiVersions` v5, `Metadata`
  v9–12, `Fetch` v12–13 by TopicID, `CreateTopics` v5–7, `DeleteTopics` v6 by
  TopicID. Recreated topics receive a fresh UUID and stale IDs answer
  `UNKNOWN_TOPIC_ID`. Report: `docs/reports/c18a-topic-ids.md`.
- **KIP-848 next-generation consumer groups** (item 18, ADR 0033, format level 5,
  snapshot v10): `ConsumerGroupHeartbeat` (68), `ConsumerGroupDescribe` (69),
  `DescribeTopicPartitions` (75), server-side `range` and `uniform` assignors,
  and incremental cooperative reconciliation without stop-the-world rebalances.
  Tested with Apache Kafka Java client 4.4.0 (`group.protocol=consumer`) and
  `kafka-consumer-groups.sh --describe`. Report: `docs/reports/c18-kip848.md`.
- **Fetch from the nearest replica** (item 19, ADR 0031): `-peers id=...@rack`,
  KIP-392 `Fetch` v11 preferred read replica, follower serving of committed data
  with `OFFSET_NOT_AVAILABLE` above the local high watermark. Report:
  `docs/reports/c19-follower-fetch.md`.
- **Additional application fault kinds** (item 23a): `expire`, `emptyfetch`,
  `slowfetch`, and `outofrange` in `-faults`. Report: `docs/reports/a23a-fault-kinds.md`.
- **Profiles and `samsa doctor`** (item 24): `-profile dev|test|prod` and
  `samsa doctor` reporting active settings, their sources, and operational risks.
  Guide: `docs/guides/configuration.md`.

## Upgrading from earlier releases

Rolling restart one node at a time with SIGTERM (`TestRollingUpgrade`). Format
levels 4 (topic IDs) and 5 (KIP-848 groups) raise automatically once every voter
runs v0.7.0 or later.
