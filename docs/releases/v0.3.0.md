# Samsa v0.3.0: proven on real processes, application fault testing, and 24-hour soak

Production plan milestone v0.3 (`docs/PRODUCTION.md`, items 4, 5, 5b, and 6).

## What is new

- **Black-box chaos test of the real binary** (A4): three real `samsa`
  processes behind user-space TCP proxies injecting kills, graceful stops,
  peer isolations, one-way link cuts, delays, and resets from a seed, judged
  by the simulator's `sim.Model` (`make chaos`). Catches a build with leader
  lease and CheckQuorum disabled. Report: `docs/reports/a4-chaos.md`.
- **Simulator tools** (A3): fault numbering and delta-debugging seed shrinking
  (`Shrink`), self-contained HTML timeline rendering (`-timeline`), fault
  coverage table, and mutation score reporting across 200 seeds per deliberate
  bug. Report: `docs/reports/a3-sim-tools.md`.
- **Application fault testing** (5b, ADR 0018): `-faults seed=N,rate=R,kinds=...`
  injects repeatable protocol-level faults (`lostack`, `notleader`, `rebalance`,
  and with item 23a `expire`, `emptyfetch`, `slowfetch`, `outofrange`) into
  client responses; `samsa verdict` inspects the broker's log offline and
  reports whether a pipeline processed every input record once, duplicated any,
  or committed past unprocessed records. Guide:
  `docs/guides/testing-applications.md`. Reports: `docs/reports/a5b-app-faults.md`,
  `docs/reports/a23a-fault-kinds.md`.
- **24-hour soak and resource bounds** (G5, item 6): `make soak` (`TestSoak`)
  runs a 24 h workload (500 records/s of 1 KiB random values, 256 MiB retention,
  producer ID churn with 10 m expiry, consumer group rebalance churn, and 1/s
  connection churn). Run 1 found `Raft.terms` growing 8 bytes per entry forever
  (`docs/BUGS.md` L1), fixed by `termIndex` (`internal/raft/terms.go`). Run 2
  on the fixed build passed: 43,196,136 records produced and consumed, 0 errors,
  0 gaps, RSS 18–32 MiB (25 MiB at 24 h), data directory 29–256 MiB, and
  63 ms start-up time on the soaked data. Report: `docs/reports/g5-soak.md`,
  raw data in `docs/soak/run1/` and `docs/soak/run2/`.

## Upgrading from v0.2.0

Snapshot encoding writes the oldest format version that holds the cluster's
state, and rolling upgrades from v0.2.0 are gated by the cluster format level
(item 10, `docs/reports/g7-rolling-upgrade.md`).
