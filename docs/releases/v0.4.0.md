# Samsa v0.4.0: TLS, SASL, ACLs, and replicated SCRAM credentials

Production plan milestone v0.4 (`docs/PRODUCTION.md`, items 7, 8, and 8b).

## What is new

- **TLS and SASL** (C5, ADR 0019): TLS for client listeners and mutual TLS
  between peers (`-tls-cert`, `-tls-key`, `-tls-ca`, `-peer-tls-*`); SASL
  `PLAIN`, `SCRAM-SHA-256`, and `SCRAM-SHA-512` implemented in the pure core
  (`internal/scram`, `internal/broker/sasl.go`) using only the Go standard
  library. Report: `docs/reports/c5-tls-sasl.md`.
- **ACLs** (C8, ADR 0020): replicated `CreateAcls` (API 30), `DeleteAcls`
  (API 31), and `DescribeAcls` (API 29) with `StandardAuthorizerData` matching
  rules (`LITERAL` and `PREFIXED` patterns, `ALLOW` and `DENY`, super-users,
  and default-deny when `-acl` is enabled). Report: `docs/reports/c8-acls.md`.
- **Replicated SCRAM credentials and follower forwarding** (C8b, ADR 0021):
  `DescribeUserScramCredentials` (API 50) and `AlterUserScramCredentials`
  (API 51) replicate salted server and stored keys through the Raft log so
  credential changes take effect across the cluster without a restart;
  followers forward `CreateAcls` and `DeleteAcls` to the leader over the peer
  channel so `kafka-acls.sh` works against any node. Found and fixed
  `docs/BUGS.md` S8 in Raft leadership transfer abandonment. Report:
  `docs/reports/c8b-credentials-forwarding.md`.

## Evidence

## Upgrading from v0.3.0 / v0.2.0

Replicated ACLs and SCRAM credentials require cluster format level 1, which the
leader raises automatically once every voter in the cluster runs a build that
supports it (`docs/reports/g7-rolling-upgrade.md`).
