# ADR 0020: ACLs as replicated commands, Kafka's authorizer rules

Date: 2026-11-14. Status: accepted. Design: `docs/design/c8-acls.md`.

## Context

Production plan item 8: ACLs as replicated commands, through the Kafka ACL
APIs, with an allowed and a denied test for every API and a default-deny
mode. Item 7 (ADR 0019) supplies the authenticated user. The semantics
were read from Kafka's sources on 2026-11-14 (design, section 1).

## Decision

- **CreateAcls (30), DeleteAcls (31), DescribeAcls (29), versions 1 to 3.**
  These are the versions Kafka 4 accepts, and the Java client 4.4 and
  franz-go v1.22.3 negotiate version 3.
- **ACLs are state applied from the log.** One command per creation and
  per delete filter. They are kept in snapshots (version 5) and in the
  state hash. Only the leader proposes; any node describes.
- **The decision is `StandardAuthorizerData`'s,** as a pure function:
  - super users pass;
  - a matching DENY wins;
  - otherwise a matching ALLOW;
  - otherwise, if the resource has no ACL at all, the configured default;
  - otherwise denied.

  ALL, the implied operations of ALLOW ACLs, `User:*`, hosts (`*`, exact
  or CIDR), literal, `*` and prefixed names all follow Kafka.
  InitProducerId uses `authorizeByResourceType` for its WRITE-on-any-topic
  fallback.
- **Each handler checks what KafkaApis checks,** in the same order, with
  the same error codes. That includes hiding, from all-topics Metadata
  and OffsetFetch, the topics a client may not describe.
- **The principal is `User:<SASL user>` or `User:ANONYMOUS`.** The host is
  the connection's IP address, which `sys.Handler.OnConnOpen` now carries.
- **Configuration:** `-acl`, `-super-users`, `-allow-if-no-acl`. Default
  deny. Without `-acl` nothing changes, and the ACL APIs answer
  SECURITY_DISABLED.
- **`net/netip` joins the core's allowlist** for parsing CIDR ranges.

## Alternatives

- **ACLs in a file, like the SASL users.** Rejected: the plan asks for the
  Kafka ACL APIs. ACLs change often, and a restart per change is not
  acceptable.
- **Hosts `*` only,** refusing anything else. It would have left the
  `sys` interface alone. Rejected: host-restricted ACLs are common. The
  change was one parameter, and the simulator passes a constant.
- **Simulated ACL changes.** Deferred: see the design, section 3.
- **Forwarding ACL changes from followers to the leader,** as Kafka
  forwards to its controller. Not done here: it is a general mechanism
  for every admin write. Until then, a follower answers NOT_CONTROLLER.
- **Replicated SCRAM credentials (API 51)** in this item. Split out as
  item 8b.

## Consequences

- With `-acl`, a client without ACLs can do nothing but log in, ask
  ApiVersions and describe the cluster.
- The Java admin client may send an ACL change to a follower and fail;
  retrying until it reaches the leader is the workaround.
- Three more APIs in ApiVersions moved every simulator seed, as ADR 0019
  predicted. `TestShrink` uses seed 5.
- Snapshots written by this build cannot be read by older builds.
